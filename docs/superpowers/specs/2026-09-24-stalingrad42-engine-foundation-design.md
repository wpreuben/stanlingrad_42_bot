# Stalingrad ’42 게임 엔진: 공통 계약과 원천 데이터 설계

## 목표와 범위

최종 목표는 제공된 영문 규칙서 **Stal42_RULES-2025-Final_LoRes.pdf**(v2.1, 2025년 4월)의 기본 규칙 §§1–24, 선택 고급 규칙 §§25–29, 캠페인 전용 규칙 §§30–34 및 시나리오 S1–S4를 처리하는 결정론적 Python 게임 엔진이다. 별도 확장판 Little Saturn/Winter Storm은 이 목표에 포함하지 않는다. 엔진은 게임의 합법성과 결과만 결정한다. 평가함수, 탐색, 전략적 판단, UI는 범위 밖이다.

전체 구현은 아래처럼 각각 검증 가능한 단위로 나눈다. 이 문서는 **첫 단위만** 상세 설계한다.

1. 공통 계약과 원천 데이터: 상태, 행동, 전이, 시리얼화, 난수, 규칙 데이터 검증, S1 초기 상태.
2. 기본 규칙의 이동·ZOC·스택·전투·손실·후퇴·전진·돌파 전투.
3. 보급·철도·자원·특수 유닛·보충·증원·날씨·승리와 S1–S3 완전 진행.
4. 선택 고급 규칙, 캠페인 전용 규칙 §34를 포함한 비공개 정보, S4 완전 진행 및 S1–S4 통합 검증.

첫 단위의 S1 초기화와 페이즈 진행은 **완전한 플레이 가능 상태를 뜻하지 않는다**. 이후 단위가 구현할 규칙이 필요한 행동은 명시적인 `RuleNotImplementedError`로 거부한다. 미구현 규칙을 합법 행동으로 간주하거나 자동 건너뛰지 않는다.

## 권위 자료와 데이터화

- 규칙 효과와 순서는 로컬 영문 규칙서 v2.1을 기준으로 한다. `02_game_engine_instructions.md`는 엔진 구조와 품질 기준이다.
- `data/glossary.csv`의 `term_id`를 규칙 내부의 고정 식별자로 최대한 재사용한다. `docs/glossary_notes.md`에 적힌 판본 차이와 미확정 용어를 존중한다. 한글·영문 표시어로 분기하지 않는다.
- `Images/`의 지도, 카운터, 시작 배치 카드, 증원표, 플레이어 에이드는 기계 판독 데이터로 옮길 때 대조 자료로 사용한다. 이 이미지 일부는 2019년판이므로 2025년 영문 규칙과 충돌하면 후자를 우선한다.
- 지도는 헥스와 여섯 방향의 인접 관계, 각 변의 도로·철도·강·통행 제한, 헥스 지형·도시·승리 지점, 지도 가장자리와 진입 구역을 가진 데이터로 표현한다. 그림 파일은 규칙 판정에 직접 사용하지 않는다.
- 첫 단위의 지도 데이터 범위는 S1이 사용하는 **Map A의 모든 플레이 가능 헥스**다. S1 시작 배치 카드의 양 진영 유닛, 초기 마커와 시나리오 설정을 옮긴다. 다른 지도와 증원표는 후속 단위에서 확장한다.
- 전사된 각 데이터 묶음에는 원본 파일명, 판본, 규칙 절 또는 카드 영역을 기록한다. 판독 불가·자료 충돌은 `docs/rule_issues.md`에 원문 위치와 현재 처리 상태 `TODO_RULE_REVIEW`로 기록하고, 해당 데이터에 의존하는 초기화나 행동을 성공 처리하지 않는다.

## 구성 요소와 책임

### 정적 규칙 데이터

`MapDefinition`, `UnitDefinition`, `ScenarioDefinition`은 지도·카운터·시나리오의 변하지 않는 사실을 제공한다. 각 정의에는 안정적 ID와 자료 판본을 둔다. 시나리오 정의는 사용 지도, 시작 턴·페이즈·진영, 시작 배치, 적용 규칙 묶음을 가리킨다. 다른 시나리오도 동일한 형식으로 추가한다.

정적 정의를 게임 상태에서 분리해 상태 복사를 작게 유지한다. `GameState`는 `ruleset_id`와 `scenario_id`로 정확한 정의 집합을 참조하며, 정의 내용의 변경이 저장된 게임을 조용히 바꾸지 않도록 데이터 판본을 검증한다.

### 동적 게임 상태

`GameState`는 턴, 날씨, 활성 진영, 현재 페이즈와 세부 결정 단계, 유닛 위치·스텝·상태, 마커, 통제·보급·자원, 증원·보충, 승리 점수와 결과, 난수 상태, 적용된 규칙 옵션을 담는다. 첫 단위에서는 아직 사용하지 않는 동적 영역도 직렬화 가능한 형태로 정의한다. 규칙상 비공개 연결 정보는 최종적으로 이 상태 안에 보관한다.

카운터 면의 `steps`와 `face_state`는 별개다. §18.2의 포병 지원 사령부는 준비/사용 면 모두 1단계이므로, 시작 배치와 저장 상태가 선택한 면을 보존한다. 상태 JSON 스키마는 이 필드 추가 시 v2로 올리고 행동·카탈로그 스키마는 v1을 유지한다.

호출자가 이전 `GameState`를 바꿀 수 없게 하고 전이는 새 상태를 반환한다. 엔진 외부의 직접 변경은 공식 입력으로 인정하지 않는다. 사건 기록은 상태 전이 결과와 연결하되 상태 해시는 향후 게임 결과에 영향을 주는 필드만 대상으로 한다.

### 행동과 결정 단계

`Action`은 타입, 행동 진영, 필수 파라미터가 명시된 값 객체이며 JSON으로 저장·복원할 수 있다. `get_legal_actions(state)`는 현재 진영과 결정 단계에서 합법적인 행동만 안정적인 순서로 반환한다. 이동 경로와 전투 후 선택처럼 단계가 여러 개인 행동은 `pending_decision`을 상태에 기록하고 각 선택을 별도 행동으로 처리한다.

`apply_action(state, action)`은 현재 단계와 행동의 진영·파라미터·합법성을 확인한 뒤 새 상태를 반환한다. 불법 행동은 유형이 있는 오류로 거부하고 입력 상태를 그대로 둔다. `PassAction`과 `EndPhaseAction`은 해당 단계의 필수 처리가 끝났을 때만 합법이다. 아직 구현하지 않은 규칙이 필요한 단계에서는 엔진이 명시적으로 중단한다.

### 페이즈와 난수

페이즈 그래프는 규칙 §3을 그대로 따른다: 날씨 → 추축군 초기·이동·전투·회복·보급 → 소련군 초기·이동·전투·회복·보급 → 승리 판정. 증원과 보충은 별도 상위 페이즈가 아니라 각 진영 초기 페이즈의 활동이다. 시나리오 시작점과 예외 턴 순서는 시나리오 데이터로 지정한다.

난수는 엔진 인터페이스로만 소비한다. `GameState`에 시드와 진행 상태를 보존하여 같은 초기 상태와 행동 순서가 같은 주사위 결과를 낸다. 기록에는 각 주사위 호출의 이유와 값을 남긴다. 첫 단위는 난수 계약과 재현성만 검증하며 날씨·전투 표 적용은 해당 규칙 단위에서 구현한다.

### §34 비공개 정보

§34 Maskirovka는 최종 엔진의 **내부 규칙**이다. 실제 예비군과 숨긴 마커의 연결, 수용 상자의 유닛, 교환·공개·제거 조건은 `GameState`와 엔진 전이로 처리한다. 규칙서상 추축군은 수용 상자의 내용은 알지만 어느 예비군이 어느 상자와 연결되는지는 알지 못한다. 캠페인 규칙 단위에서 이 경계에 맞는 진영별 정보 조회도 엔진이 제공한다. 첫 단위는 이 정보를 표현할 수 있는 상태 구조를 확보하지만 §34의 실제 행동은 구현하지 않는다.

## 외부 계약

최종 엔진은 `new_game(scenario_id)`, `get_legal_actions(state)`, `apply_action(state, action)`, `is_terminal(state)`, `get_result(state)`, `serialize_state(state)`, `deserialize_state(data)`를 제공한다. 첫 단위에서는 S1 초기화, 상태·행동 저장과 복원, 지원되는 페이즈의 합법 행동과 전이를 구현한다. 아직 지원하지 않는 규칙을 요청하면 명시적으로 오류를 반환한다.

상태·행동의 JSON에는 스키마 판본을 포함한다. 복원 시 필수 필드, enum 값, ID 참조, 데이터 판본, 난수 상태를 검증한다. 이벤트는 기계 판독 가능한 타입과 파라미터를 기본으로 기록하고 표시 문장은 별도 변환으로 만든다.

## 검증과 첫 단위 완료 기준

- Map A의 모든 헥스 ID가 유일하고, 인접 관계가 양방향이며, 변 속성이 양쪽에서 일치한다.
- S1 배치의 모든 유닛 ID가 유일하고 정의된 유닛·헥스 또는 진입 구역을 가리킨다. 시작 턴·페이즈·진영은 S1.1–S1.2와 일치한다.
- 상태와 행동을 저장·복원하면 의미상 같은 값이 된다. 알 수 없는 ID, 잘못된 판본, 손상된 난수 상태는 거부한다.
- 같은 시드와 같은 행동 순서는 동일한 상태와 사건 기록을 만든다.
- 규칙 §3의 페이즈 순서와 진영 교체를 검증하고, 필수 결정을 건너뛰는 행동은 거부한다.
- 불법 행동 뒤에도 입력 상태와 난수 진행 상태는 바뀌지 않는다.
- 규칙 번호를 테스트 이름 또는 주석에 남기고 지도 가장자리·턴 경계·중복 ID·누락 자료를 포함한다.
- 미구현 이동·전투·보급 등의 호출은 성공을 가장하지 않는다. 후속 단위가 완성되면서 해당 오류를 실제 합법 행동과 전이로 대체한다.

## 남은 단위와 명세 경계

다음 설계는 이 문서의 ID·상태·행동·전이·난수 계약을 사용한다. 각 규칙 단위는 영문 룰북의 규칙 번호별 사례와 실제 시나리오의 고정 상태를 테스트로 추가한다. 전체 완료 판정은 S1–S4의 시작, 모든 관련 행동, 턴 진행, 승리 판정, 저장·복원, 시드 재현을 통합 검증한 뒤에만 내린다.
