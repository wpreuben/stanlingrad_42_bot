# Map A 전사 진행 기록

원본: `Stal42_Map_west-FINAL-150 Q12.jpg` (3300×5100, 제공된 2019년 지도). 지형 기호 대조용: `images_high/STAL42_TEC-100 Q12.jpg`. 규칙 효과는 2025년 영문 규칙서를 우선한다. 원본 이미지는 저장소에 포함하지 않는다.

## 격자 감사

원본에서 직접 확인한 `1300`, `1301`, `1600` 등의 중심을 기준으로, 헥스 중심 후보 1,376개를 찾았다. 이미지 색상만 이용한 **미검증 분류**는 육지 가능 1,198개, 비육지 가능 130개, 직접 검토 필요 48개다. 이 수치는 플레이 가능한 헥스 수가 아니다. 바다·지도 밖·트랙, 강과 도시처럼 색이 다른 실제 헥스가 섞여 있다.

원본 확대 대조에서 확인한 사례:

| ID | 판독 | 근거 |
|---|---|---|
| `1300`, `1301` | 육지 헥스 | 지도 북서쪽 2군 배치 영역의 인쇄 번호와 수평 공유 변 |
| `1003` | 도시 헥스 | 쿠르스크 인쇄 영역. 옅은 바탕색 비율이 낮아도 실제 헥스 |
| `1000`, `1100` | 지도 밖 | 북서쪽 회색 여백에는 해당 인쇄 헥스가 없음 |
| `1037` | 지도 밖 | 추축군 마커 영역 |
| `2038`, `2039` | 해안 재검토 | 아조프해의 번호 있는 헥스다. `2038`에는 밝은 육지 쐐기가 보이며 `2039`도 해안 경계에 걸친다. 순수 바다로 단정하지 않고 §2.2.3의 플레이 가능성 기준에 따라 다시 판독한다. |
| `2438` | 해안 재검토 | 예이스크 동쪽의 번호 있는 파란 헥스다. 확대하면 남쪽 변을 따라 밝은 육지 조각이 있어 순수 바다로 단정하지 않는다. |

영문 규칙서 v2.1 §2.2.3은 바다로 완전히 덮인 헥스변을 통과 불가로 정하고, 어두운 해안 조각은 무시하되 나머지 육지는 플레이 가능하다고 명시한다. §5.7.1은 해상 이동을 Shipping Path로 처리하고, 부대가 바다에 남을 수 없다고 명시한다. 따라서 번호가 있어도 순수 바다 헥스는 `map_a.json`의 육상 그래프에서 제외한다. 육지가 남은 해안 헥스는 포함하고, 육지끼리 맞닿은 변이 바다로 완전히 덮인 경우 `impassable_hexside`로 표시한다. 항구 사이 해상 항로는 후속 규칙 자료에서 별도로 모델링한다. 현재 카탈로그는 미완성 지도 파일을 성공적으로 읽지 않도록 한다.

## 남은 검수

### 북서쪽 지형·연결 1차 검수

원본 좌상단 `x=0–850, y=0–900`을 확대해 `1200`–`1202`, `1300`–`1302`, `1400`–`1402`의 아홉 헥스가 모두 평지임을 판독했다. 이 아홉 헥스 사이에서 실제로 공유하는 16개 변의 방향을 [`map_a_northwest_edges.csv`](map_a_northwest_edges.csv)에, 헥스 지형을 [`map_a_northwest_hexes.csv`](map_a_northwest_hexes.csv)에 기록했다. 지도 확대본과 TEC의 도로 기호를 대조해 `1200→1301`, `1301→1302`, `1302→1402`의 변을 `secondary_road`로, 나머지 13개 내부 변을 교차 특성 없음으로 확인했다. 아홉 헥스의 도시·항구 등 헥스 특성도 없음으로 확인했다. 두 CSV는 **부분 검수 기록**이며 전체 이웃 목록이 아니다. 영역 바깥으로 이어지는 변과 인접 헥스는 아직 검수되지 않았으므로 빈 변으로 해석하면 안 된다. 이 파일들은 실행용 `map_a.json`으로 읽지 않는다.

지형 효과표를 대조하면서 지도 계약에도 `primary_road`와 `secondary_road`, `lake_hexside`와 `alpine_hexside`, `town`과 `landmark`를 구분하도록 추가했다. 도로의 두 종류는 진창 시 이동 비용이 달라 동일한 `road` 변 속성으로 합칠 수 없다. 이 구분은 실제 지도 변을 확정했다는 뜻이 아니다.
카탈로그 검증기는 4자리 지도 헥스 ID의 열 홀짝에 따른 여섯 방향 좌표도 검사한다. 두 헥스가 서로를 이웃이라고 적더라도 실제 인쇄 격자에서 변을 공유하지 않으면 자료 오류로 거부한다. 이 검사는 존재·지형·변 속성의 육안 검수를 대신하지 않는다.

### 테르부니 주변 지형·연결 검수

원본 `x=1060–1430, y=60–490` 확대 영역에서 `2000`–`2002`, `2100`–`2102`, `2200`–`2202` 아홉 헥스의 평지와 16개 내부 공유 변을 대조했다. [`map_a_terbuny_hexes.csv`](map_a_terbuny_hexes.csv)의 `2100`은 흰 원이므로 TEC의 `landmark`다. [`map_a_terbuny_edges.csv`](map_a_terbuny_edges.csv)에는 철도 변 3개, 보조도로 변 3개, 횡단 특성이 없는 변 10개를 기록했다. Olym 강의 서쪽 접경은 아래 기록에 추가했으며 다른 외부 연결은 아직 기록하지 않았다. 두 CSV는 실행용 지도 자료가 아닌 부분 검수 기록이다.

서쪽 `x=850–1160, y=45–455` 확대 영역에서 `1800`–`1802`, `1900`–`1902` 여섯 헥스와 9개 내부 공유 변을 대조했다. [`map_a_olym_edges.csv`](map_a_olym_edges.csv)에는 앞서 기록한 `2000`–`2002`와 맞닿는 Olym 강변 5개를 `minor_river`로 기록했다. 강이 해당 헥스변을 따라가고, 교량 표시는 보이지 않는다. [`map_a_olym_hexes.csv`](map_a_olym_hexes.csv)의 여섯 헥스는 평지다. 이 구역 서쪽 Kshen 강변은 아래 기록에 추가했고, 그 밖의 외부 변은 미검수다.

`x=585–970, y=45–475` 확대 영역에서는 `1500`–`1502`, `1600`–`1602`, `1700`–`1702` 아홉 헥스와 16개 내부 공유 변을 추가로 대조했다. [`map_a_tim_kshen_edges.csv`](map_a_tim_kshen_edges.csv)에 Tim 강변 5개, `1800`–`1802`로 이어지는 Kshen 강변 5개, `1600→1601→1602` 보조도로 2개를 기록했다. TEC의 붉은 빗금과 일치하는 `1502`, `1600`, `1601`은 인쇄된 방어시설(`fortification`)로 [`map_a_tim_kshen_hexes.csv`](map_a_tim_kshen_hexes.csv)에 표시했다. 아직 연결을 적지 않은 바깥 헥스변은 미검수다.

부분 검수 CSV는 `uv run --locked python -m tools.map_fragment_audit docs`로 묶어서 검사한다. 이 도구는 검수한 헥스끼리의 인접 변 누락(구역 경계 포함), 좌표 오류, 중복 변, 모르는 지형·특성 ID를 거부한다. 아직 검수하지 않은 헥스로 향하는 연결의 완전성과 그림 판독 자체는 검사할 수 없으므로 전체 `map_a.json`의 완료 판정에 사용하지 않는다.
현재 구역별 부분 검수 합계는 헥스 76개, 변 170개, 인쇄 승점 1점이다. 변 특성의 내역은 보조도로 23개, 주도로 2개, 철도 10개, 소하천 23개, 대하천 5개이며, 나머지 107개 변에는 횡단 특성이 없다.

### 전사 후보 생성과 이미지 검토 순서

인쇄 ID 1,042개와 검수된 부분 CSV에서 [`map_a_edge_candidates.csv`](map_a_edge_candidates.csv)를 생성했다. 격자 좌표로 가능한 이웃 변 2,947개를 한 번씩 나열하며, 그중 기존 검수 변 170개만 `reviewed`와 확정된 `crossing_features`·출처를 갖는다. 나머지 2,777개는 `unreviewed`이고 속성이 빈칸이다. 인쇄 ID에는 바다 헥스도 있으므로 이 후보 목록은 통행 가능 지도 그래프가 아니다. 검수 자료를 바꾸면 아래 명령으로 다시 생성한다.

```bash
uv run --locked python -m tools.map_edge_candidates --output docs/map_a_edge_candidates.csv
```

2019년 제공 지도 이미지(3300×5100)에서 각 후보 변 중심의 29×29픽셀을 검사해 파란 픽셀이 25개 이상인 미검수 변 483개를 [`map_a_river_review_queue.csv`](map_a_river_review_queue.csv)에 모았다. `map-tools` 의존성 그룹의 Pillow는 이 보조 도구에만 필요하며 게임 엔진의 실행 의존성에는 넣지 않았다. 검수된 변 170개를 기준으로 이 신호는 강 변 28개 중 25개를 잡았고 강이 아닌 변 142개 중 5개도 표시했다. 따라서 **강 판정이나 빈 변 확정에는 사용할 수 없으며**, 표시되지 않은 변도 후속 육안 검수가 필요하다.

첫 대조로 Savala 주변 `3600→3701`, `3700→3701` 후보를 확대 원본에서 확인했다. 두 변의 강 표시는 보이지만 `3600→3701`에는 철도도 가로지르므로, 교량 속성까지 확인하기 전에는 검수 CSV로 승격하지 않는다.

```bash
uv run --locked --group map-tools python -m tools.map_image_evidence \
  '../../images_high/Stal42_Map_west-FINAL-150 Q12.jpg' \
  --output docs/map_a_river_review_queue.csv
```

| 17 | `1700`–`1706` |
| 18–41 | 각 열에서 `00`–`06` 행의 헥스 ID를 확인함 (`1800`–`1806`부터 `4100`–`4106`까지, 열마다 7개) |

북쪽 띠를 네 구간으로 확대해 총 224개의 인쇄 ID를 확인했다. `18`–`41`열에서는 앞선 구간과 겹치지 않는 `00`–`06`행만 위 표에 적었다. 왼쪽 위 회색 여백에는 `1000`과 `1100` 헥스가 없다. 북쪽 경계의 `1300`은 아래 `1301`, 아래 오른쪽 `1400`, 아래 왼쪽 `1200`과 변을 공유한다. `1200`은 위 오른쪽 `1300`, 아래 오른쪽 `1301`, 아래 `1201`, 아래 왼쪽 `1101`과 변을 공유한다. 이 연결은 지도 그림에서 확인한 일부 사례이며, 나머지 헥스의 연결을 산술적으로 확정하지 않았다.

이어 원본의 세로 800–1700픽셀 영역도 네 구간으로 확대했다. `10`–`41`의 각 열에서 `07`–`13`행의 인쇄 ID를 확인했다(`1007`–`1013`부터 `4107`–`4113`까지). 앞선 북쪽 띠와 중복되는 `1107`, `1307`을 빼면 **고유한 헥스 ID 446개**가 원본과 대조됐다. 이 중 오른쪽 경계의 `4100`–`4111`은 2025년 영문 규칙 S1.2가 지정하는 5예비군 진입 범위 전체다. 강·철도·도로·산림과 도시의 판정은 아직 전사하지 않았고, 이 ID 확인만으로 `map_a.json`을 생성하지 않는다.

다음 세로 1600–2500픽셀 영역에서는 `18`–`41` 각 열의 `14`–`20`행 ID를 확인했다(168개). 따라서 현재 **고유한 인쇄 ID 614개**를 원본과 대조했다. `10`–`17`열의 같은 행은 왼쪽 지도 경계와 Sequence of Play 상자가 겹치는 구간이 있어 일괄 범위로 기록하지 않았다. 도시·강·철도·도로가 그려진 헥스에서도 번호와 존재 여부만 확인했으며, 지형과 연결을 확정했다는 뜻은 아니다.

세로 2400–3300픽셀 영역에서는 `18`–`41` 각 열의 `21`–`27`행 ID를 추가로 확인했다(168개). 현재까지 **고유한 인쇄 ID 782개**를 대조했다. 왼쪽의 `10`–`17`열은 지도 밖 여백, 턴 기록 트랙, 플레이 가능 헥스가 섞여 있어 이번 범위 합계에서 제외했다.

세로 3200–4100픽셀 영역에서는 `18`–`41` 각 열의 `28`–`34`행 ID를 추가로 확인했다(168개). 현재까지 **고유한 인쇄 ID 950개**를 대조했다. `2030` 일대 도시, `2634` 일대 해안, `3334` 일대 습지처럼 지형이 다른 곳도 인쇄 번호만 확인했다. 순수 바다 여부와 플레이 가능 여부는 이 합계에 포함되지 않으며 별도 판단이 필요하다.

세로 4000–5000픽셀 영역에서는 동쪽 `33`–`41` 각 열의 `35`–`42`행 인쇄 ID를 추가로 확인했다(72개). 현재까지 **고유한 인쇄 ID 1,022개**를 대조했다. 같은 영역의 서쪽에는 번호가 있는 아조프해 헥스와 해안 육지 헥스가 함께 보인다. 이들은 따로 플레이 가능 여부를 가려야 하므로 이번 합계에 넣지 않았다.

S1 시작 배치 CSV의 고유 헥스 96개를 위 기록과 비교해 빠진 20개를 각 이미지 영역에서 개별 확인했다. 이 중 `1936`, `2338`, `2936`, `3139`, `3241`은 남쪽 해안·도시 영역에 있다. [`map_a_printed_id_checks.csv`](map_a_printed_id_checks.csv)는 지금까지 **1,042개 인쇄 ID**와 확인한 이미지의 세로 구간을 기록한다. `printed_id_only`는 번호 판독만 완료했다는 뜻이다. S1의 96개 시작 헥스 ID가 모두 이 목록에 있지만, 지형·플레이 가능성·헥스변 정보가 확인됐다는 뜻은 아니다.

1. 후보마다 인쇄 번호, 경계 헥스의 존재, 육지·바다·지도 밖을 확인한다.
2. 여섯 방향 `n/ne/se/s/sw/nw`의 이웃과 변을 양쪽에서 확인한다.
3. 지형과 도시·항구·승점 수치, 도로·철도·강·교량·나루터를 원본과 대조한다.
4. 검수한 영역과 헥스 개수를 `sources.json`에 기록한 뒤 `map_a.json`을 완성한다. 그때 보류 중인 Map A 테스트를 활성화한다.

후보 산출용 스크립트와 전체 1,376개 중심의 색상 점수는 현재 작업 브랜치의 `.superpowers/sdd/2026-09-24-stalingrad42-engine-foundation/`에 임시 보관한다. 이 점수는 지형 판정에 사용하지 않는다.

S1 시작 카드에서 뽑은 지도 배치 묶음 98개(`docs/s1_start_card_locations.csv`)의 헥스 ID는 모두 후보 격자에 있다. 이는 **격자 좌표의 산술적 일치**만 확인한 결과다. 실제 플레이 가능 여부와 지형·헥스변은 원본 지도 대조를 마친 뒤 확정한다.
